# 사주명리학 × 심리학 엔진 — 기획/설계서

> 목표: 사주를 "점(占)"이 아니라 **자기이해 도구**로 리프레이밍한 해석 엔진을 만들고,
> 이를 기반으로 Threads / X에서 운영하는 **사주 콘텐츠 스레드**를 자동화한다.

---

## 1. 포지셔닝 — 왜 이 조합인가

| 기존 사주 콘텐츠 | 우리의 차별점 |
|---|---|
| "올해 재물운이 좋다/나쁘다" 단정형 | "너는 이런 기질이라 이런 상황에서 이렇게 반응하는 경향이 있다" 성찰형 |
| 맞다/틀리다 논쟁 유발 | 저장·공유 욕구 자극 (자기인식 콘텐츠) |
| 미신 거부감 | 심리학 프레임으로 진입장벽 제거 |

**핵심 메시지:** "사주는 운명이 아니라 기질의 지도다."

---

## 2. 시스템 아키텍처 (2단 분리)

계산과 해석을 반드시 분리한다. 계산은 결정론적으로 정확해야 하고, 해석은 창의적이어야 한다.

```
[입력] 생년월일 + 출생시각 + 출생지(경도)
        │
        ▼
┌─────────────────────────────┐
│ [1] 계산 코어 (만세력 엔진)        │   ← LLM 사용 안 함. 100% 결정론적 계산.
│  - 양력/음력 변환                 │
│  - 절기(節氣) 경계 판정            │
│  - 진태양시 보정 (경도 → 시주 결정) │
│  - 사주팔자(천간4·지지4) 산출       │
│  - 오행 분포 / 십신 / 십이운성      │
│  - 대운(大運) · 세운(歲運) 타임라인  │
└─────────────────────────────┘
        │  (구조화 JSON)
        ▼
┌─────────────────────────────┐
│ [2] 해석 레이어 (사주 × 심리학)     │   ← Claude API 사용.
│  - 매핑 규칙 DB 주입               │
│  - 톤/포맷 템플릿 적용             │
│  - 콘텐츠 타입별 출력 (스레드/카드)  │
└─────────────────────────────┘
        │
        ▼
[출력] 스레드 초안 → 사람 검수 큐 → 게시
```

> ⚠️ **가장 어려운 건 [1]번이다.** 절기 경계·진태양시·60갑자 순환에서 한 글자라도 틀리면
> "이 사주 틀렸다"는 신뢰 붕괴가 일어난다. 검증된 만세력 데이터/라이브러리로 산출하고,
> 알려진 사례(연예인 생일 등)로 회귀 테스트를 만든다.

## 3. 핵심 IP — 사주 → 심리학 매핑 규칙

이 매핑 테이블이 제품의 진짜 자산이다. 아래는 v1 초안.

### 3.1 오행(五行) → 기질

| 오행 | 키워드 | 심리 특성 (Big Five 경향) | 과다/결핍 시 그림자 |
|---|---|---|---|
| 목(木) | 성장·추진·인정욕구 | 외향성↑ 개방성↑ | 과다: 조급·분노 / 결핍: 결단력 저하 |
| 화(火) | 표현·열정·사교 | 외향성↑ 충동성↑ | 과다: 변덕·번아웃 / 결핍: 표현 억압 |
| 토(土) | 안정·신뢰·중재 | 성실성↑ 안정애착 | 과다: 고집·정체 / 결핍: 불안정 |
| 금(金) | 원칙·결단·완벽 | 성실성↑ 친화성↓ | 과다: 경직·비판 / 결핍: 우유부단 |
| 수(水) | 사고·유연·통찰 | 개방성↑ 내향사고 | 과다: 회피·불안 / 결핍: 융통성 저하 |

오행의 **균형/편중** 자체가 심리 안정성 지표 → "한쪽이 과한 사람의 패턴" 콘텐츠로 직결.

### 3.2 십신(十神) → 동기·관계 구조

| 십신 | 심리학적 의미 |
|---|---|
| 비견·겁재 | 자아·독립·경쟁 (자존감, 주도성) |
| 식신·상관 | 자기표현·창의 (상관=재능+반항) |
| 정재·편재 | 현실감각·통제 (편재=모험·확장) |
| 정관·편관(칠살) | 규범·책임 (칠살=스트레스 취약/강박) |
| 정인·편인 | 수용·학습·내면 (편인=비주류 사고) |

### 3.3 일간(日干) → 캐릭터화

일간(태어난 날의 천간) = "자아의 핵심". 10천간을 12지와 조합해 캐릭터 시리즈로 IP화.
(예: "갑목 일간 = 큰 나무형 — 리더 기질이지만 휘어지지 못하는…")

### 3.4 대운(大運) → 발달심리 시즌

대운(10년 주기) = 인생의 "계절". 운세 예언이 아니라 **시기별 성장 과제**로 리프레이밍한다.
(예: "지금 너는 식상이 강해지는 시즌 — 표현 욕구가 커지는 때")

## 4. 콘텐츠 전략 (Threads / X)

### 4.1 포맷
- **훅형 단문:** "수(水)가 강한 사람의 7가지 특징" → 저장 유도
- **개인화 훅:** "생일 알려주면 기질 풀어드림" → 댓글/DM 전환
- **시리즈물:**
  - 일간 12종 캐릭터 카드
  - "오행 과다/부재" 시리즈
  - "이 조합인 사람의 연애 패턴"
  - "오늘의 기질 인사이트" (세운 기반 데일리)

### 4.2 운영 파이프라인
```
엔진이 초안 N개 자동 생성 → 검수 큐(Notion DB) → 사람이 톤 확인/선택 → 예약 게시
```
Notion을 이미 쓰고 있으니 검수 큐를 Notion DB로 두면 기존 대시보드와 자연스럽게 통합된다.

### 4.3 윤리 가드레일 (필수)
- "점술/예언"이 아닌 "자기이해 콘텐츠"로 명시
- 의료·재무·법률 단정 금지
- 결정론적 운명론 표현 금지 ("~할 수밖에 없다" ✕ → "~하는 경향" ◯)
- 해석 프롬프트에 이 규칙을 시스템 레벨로 고정

## 5. 기술 스택 제안 (현 저장소 기준)

현재: **Next.js 14 + Vercel + Notion**. 그대로 활용한다.

| 영역 | 선택 |
|---|---|
| 계산 코어 | TypeScript 모듈 (`lib/saju/`), 검증된 만세력 데이터/라이브러리 + 절기 계산 |
| 해석 레이어 | Claude API (`claude-opus-4-8` 고품질 / `claude-sonnet-4-6` 대량 생성) |
| API | Next.js API 라우트 (`pages/api/saju/*`) |
| 검수 큐 | Notion DB (`@notionhq/client` 이미 설치됨) |
| 스케줄 | Vercel Cron (`pages/api/cron/` 패턴 이미 존재) |
| 게시 | Threads/X API 연동 (수동 게시로 시작 → 자동화) |

---

## 6. 로드맵

- **Phase 0 — 설계 (현재 문서)** ✅
- **Phase 1 — 계산 코어 + 정확도 검증**
  - 만세력 산출, 알려진 사례로 회귀 테스트 통과
- **Phase 2 — 매핑 규칙 DB + 해석 프롬프트**
  - 위 3장 테이블을 데이터화, Claude 해석 프롬프트 작성
- **Phase 3 — 콘텐츠 생성 데모**
  - 샘플 스레드 5~10개 자동 생성 → 톤 검증
- **Phase 4 — 운영 자동화**
  - Notion 검수 큐 + Cron + 게시 연동

## 7. 리스크 & 결정 필요 사항

- **계산 정확도**: 만세력 라이브러리 선정이 1순위 리스크. (라이브러리 vs 자체 절기 계산)
- **톤**: "재미/밈" vs "진지한 자기성찰" — 타깃에 따라 프롬프트가 갈림
- **개인화 수준**: 생일만 받을지(약식), 시각·출생지까지 받을지(정밀) — 입력 마찰 trade-off
- **수익화**: 무료 콘텐츠로 팔로워 → 유료 정밀 리포트/구독? (후순위)
